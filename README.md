# Telegram-библиотека с AI-библиотекарем (FastAPI + Gemini)

Привет! Это мой pet-проект — асинхронный Telegram-бот для управления электронной библиотекой. 

Когда я начинал этот проект, я решил отказаться от стандартных библиотек-оберток (вроде aiogram или telebot). Мне было важно понять, как всё работает «под капотом». Поэтому всё взаимодействие с Telegram API реализовано напрямую: через FastAPI, Webhooks и формирование чистых JSON-запросов.

## Что умеет бот?

* **Автопарсинг книг (Магия AI):** Пользователь просто кидает PDF-файл в бота. Бот сам «достает» из него обложку (через PyMuPDF), отправляет картинку в нейросеть Google Gemini 1.5 Flash, а та распознает автора, название и автоматически подбирает категорию для книги.
* **Плавная пагинация (Листалка):** Никаких "простыней" из 100 сообщений в чате. Я реализовал постраничный вывод книг через SQL-запросы с LIMIT и OFFSET. При перелистывании бот не шлет новые сообщения, а аккуратно обновляет текущее через editMessageText.
* **Умная база данных:** Написан паттерн Get-or-Create на чистом SQL. База сама чистит невидимые пробелы и нормализует регистр (защита от дубликатов категорий и авторов).
* **Поиск:** Быстрый текстовый поиск по фрагментам названий и авторов (SQL LIKE).

## Мой стек технологий
* **Язык:** Python 3.12
* **Web-фреймворк:** FastAPI, Uvicorn, Requests
* **База данных:** SQLite3 (сырые SQL-запросы)
* **ИИ и работа с файлами:** Google Generative AI (Gemini), PyMuPDF (fitz), Pillow
* **Деплой (VPS):** Ubuntu 24.04, Nginx, Systemd, Certbot (SSL)

## Архитектурные решения, которыми я горжусь

1. **Победа над таймаутами Telegram (BackgroundTasks)**
   *Проблема:* Telegram требует, чтобы сервер ответил кодом 200 OK за пару секунд, иначе он начинает спамить дублями запросов. Но нейросеть часто думает дольше.
   *Решение:* Я разделил логику с помощью BackgroundTasks во FastAPI. Теперь роутер-«секретарь» моментально отдает Телеграму 200 OK (за 0.01 сек), а функция-«работяга» спокойно обрабатывает PDF и обращается к API гугла в фоновом режиме.

2. **Работа без библиотек Telegram**
   Вся логика перехватов callback_data с инлайн-кнопок, парсинг входящих апдейтов и отправка POST-запросов к Telegram API написана руками. Это дало мне полный контроль над архитектурой и глубокое понимание протокола HTTP.

3. **Бережное отношение к серверу**
   Бот не хранит гигабайты PDF-книг на жестком диске. Файлы остаются в облаке Telegram, а в моей базе данных сохраняются только легкие file_id. 

## Как запустить проект локально

1. Склонируйте репозиторий:
    ```bash
    git clone [https://github.com/ВАШ_НИК/library-tg-bot.git](https://github.com/ВАШ_НИК/library-tg-bot.git)
    cd library-tg-bot
    ```
2. Создайте виртуальное окружение и установите библиотеки:
    ```bash
    python3 -m venv venv
    source venv/bin/activate  
    pip install -r requirements.txt
    ```
3. Создайте файл config.py в корне проекта и добавьте свои данные (этот файл добавлен в .gitignore для безопасности):
    ```python
TELEGRAM_TOKEN = "токен_от_BotFather"
telegram_api_url = f"https://api.telegram.org/bot{TELEGRAM_TOKEN}"
ADMIN_ID = [123456789]
DB_NAME = "library.db"

import os
os.environ["GEMINI_API_KEY"] = "ключ_от_Google_AI_Studio"
    ```
4. Запустите сервер:
    ```bash
    uvicorn main:app --reload --port 8000
    ```
